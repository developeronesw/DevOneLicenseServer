# Phase 5 — Production Deployment

This phase moves the DevOne License Server from the tested repository into a live Cloudflare Worker + D1 deployment.

## Cloudflare resources

- Worker: `devone-license-server`
- D1 database: `devone-license-db`
- D1 binding: `DB`
- Migrations: `migrations/`
- Required Worker secret: `LICENSE_SIGNING_PRIVATE_KEY`

The production Wrangler configuration is generated by GitHub Actions from `wrangler.example.jsonc`. The real D1 database ID is never committed to the repository.

## One-time Cloudflare setup

Create the production D1 database in the target Cloudflare account:

```bash
npx wrangler d1 create devone-license-db
```

Record the returned database UUID.

Generate an Ed25519 key pair. The private key must be encoded as base64 PKCS#8 for the Worker secret. The corresponding public key will be used by DevOne CMS v2 to verify Network entitlements. Never commit either private key material or a secret value.

Set the Worker secret:

```bash
npx wrangler secret put LICENSE_SIGNING_PRIVATE_KEY
```

The secret must contain the base64 PKCS#8 Ed25519 private key.

## GitHub Actions secrets

Add these repository secrets:

- `CLOUDFLARE_ACCOUNT_ID`
- `CLOUDFLARE_API_TOKEN`
- `DEVONE_LICENSE_D1_DATABASE_ID`

The Cloudflare API token should be scoped to the production account and only the permissions required for Worker deployment and D1 operations. Cloudflare recommends storing these credentials in CI/CD secrets rather than source control.

## First deployment

Push or merge to `main`. The deployment workflow:

1. Installs dependencies.
2. Runs typecheck.
3. Runs all tests.
4. Builds the application assets.
5. Generates the production Wrangler configuration using the D1 ID.
6. Applies any unapplied D1 migrations remotely.
7. Deploys the Worker.

If the Worker secret is missing, Wrangler's required-secret validation should stop the deployment rather than creating an incompletely configured production Worker.

## Production hostname

For the final API hostname, use a Cloudflare Custom Domain when this Worker is the origin for the hostname. Example:

```text
license.example.com
```

The exact hostname should be selected before adding it to the Wrangler configuration. Cloudflare Custom Domains can create the required DNS record and certificate automatically.

Until the production hostname is selected, the deployment template leaves `workers_dev` enabled so the Worker can be smoke-tested without guessing a domain.

## Live smoke test

After deployment, verify:

```text
GET /v1/health
```

Expected response shape:

```json
{
  "ok": true,
  "data": {
    "service": "devone-license-server",
    "apiVersion": "1",
    "status": "ok"
  },
  "requestId": "..."
}
```

Then perform the full production test using a disposable installation:

1. Register installation.
2. Authenticate installation.
3. Issue a test Network license through an authorized administrative path.
4. Activate the license.
5. Verify the signed entitlement.
6. Refresh the entitlement.
7. Revoke the test license.
8. Confirm subsequent activation/refresh behavior is rejected as expected.
9. Confirm no license key, installation secret, or private signing key appears in logs.

Do not use a customer license for the first production smoke test.
